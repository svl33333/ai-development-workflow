# 新規プロジェクトへのワークフロー導入と作業開始手順

## 目的

新規プロジェクトへAI開発ワークフローを導入し、導入後にCodexからプロトタイプ開発または本番開発を開始する手順を定義する。

## 1. 新規プロジェクトへの導入

対象プロジェクトをCodexで開き、次の指示を送る。

```text
このプロジェクトに、GitHub上の共通マスター
https://github.com/svl33333/ai-development-workflow
からAI開発ワークフローを導入してください。

workflow-onboardingスキルを使用し、次を実施してください。

- 対象プロジェクトのリポジトリとルートを確認
- GitHubの共通マスターから取得する
- 取得したコミットを固定・記録する
- 管理対象ファイルを非破壊で導入する
- 既存ファイルと競合する場合は上書きせず報告する
- 導入結果を.ai-workflow/onboarding.jsonに記録する
- ChatGPT Projectの必要な名前を提示する
- ChatGPT Project作成が必要なところで停止する

ChatGPT Projectは自動作成せず、ユーザーによる手動作成を待ってください。
```

Codexは導入後、必要なChatGPT Project名を提示して停止する。

ユーザー側で指定された名前のProjectを作成し、Project-only memoryを設定した後、次を送る。

```text
ChatGPT Projectの作成が完了しました。
導入処理を再開し、Project・ワークスペース・リポジトリの紐付け、C2C接続、GitHub認証、導入状態を検証してください。
問題がなければ、現在のワークフロー状態と次の作業を提示してください。
```

### 導入される主なファイル

- `.ai-workflow/`
- `.agents/skills/`
- `.github/copilot-instructions.md`
- プロンプト、テンプレート、状態スキーマ
- 導入証跡 `.ai-workflow/onboarding.json`

導入処理は既存ファイルを自動で上書きしない。競合・検証失敗・認証不足がある場合は、導入完了扱いにせず停止する。

## 2. 導入後の作業開始トリガー

現在の作業開始は、Codexへ自然言語で指示する。承認が必要な段階では、ワークフローが停止する。

### プロトタイプを開始する場合

```text
このプロジェクトでAI開発ワークフローを開始してください。

目的:
<やりたいこと>

まず対象リポジトリと既存資料を確認し、prototype_intakeから開始してください。
軽量プロトタイプの設計・実装・テスト・評価を行い、評価結果、成功条件、失敗条件、残課題を保存してください。

本番仕様の確定、正式Issue作成、本番実装、マージはまだ行わないでください。
人間の承認が必要な段階では停止してください。
```

### 本番開発を開始する場合

```text
このプロジェクトで、本番開発ワークフローを開始してください。

対象Issue:
<GitHub Issue URL>

まずIssue、CONTEXT.md、ADR、プロトタイプ評価結果、残課題を確認してください。
仕様が未確定、承認されていない、または必要な成果物が不足している場合は実装せず停止してください。

仕様確定後は、次の順序で進めてください。

1. 実装計画をChatGPTで作成
2. 独立した同一レビュー会話で最低3ラウンドレビュー
3. Codexが指摘を反映
4. 人間が実装計画を承認
5. Codexが実装・テスト
6. ローカルPRドラフトを作成
7. ChatGPTがPRレビュー
8. Codexが修正・再レビュー
9. 人間承認後にPR公開・マージ

各承認ポイントでは停止してください。
```

### 状態確認だけを行う場合

```text
このプロジェクトのワークフロー状態を確認し、
現在の工程、承認待ち、ブロッカー、残課題、次のアクションを提示してください。
```

## 3. 人間が確認する停止点

- ChatGPT Projectの作成
- プロトタイプから本番へ移行するかどうか
- 本番仕様の確定
- 正式Issueの公開
- 実装計画の承認
- PRドラフトの確認
- PR公開
- PRマージ

## 4. 導入と作業開始の違い

- 導入: 共通スキル、設定、テンプレート、状態管理をプロジェクトへ配置する
- 作業開始: Codexへ目的またはIssueを渡して工程を開始する
- ChatGPT Project作成、仕様承認、計画承認、PR承認、マージは人間の停止点である

現時点では、導入後の全工程を無条件に自動完遂する仕様ではない。承認が必要な箇所では、ワークフローが意図的に停止する。
