# AI開発ワークフローパッケージ仕様書

- Status: draft
- Scope: 個人環境のCodex、会社環境のVS Code + GitHub Copilot

## 目的

AIによる実装速度向上に伴う理解負債を抑制し、CodexとGitHub Copilotで共通の開発フローを運用するための共通マスターを作成する。

## 基本方針

- 共通マスターは独立したGitHubリポジトリで管理する
- 共通マスターから各環境への配布・更新は一方向とする
- Codex/Copilotの差は環境別アダプターで吸収する
- 各プロダクトのオーケストレーターは各環境内で完結する
- プロトタイプフローと本番開発フローを分ける
- 仕様確定、本番移行、マージ、破壊的操作、会社ポリシー変更は人間の承認を必須にする
- 会社環境の詳細テスト結果・ログ・固有ポリシーは環境外へ自動送信しない
- 会社環境からのフィードバックは、ユーザーが機密確認後に手入力する

## フロー

### プロトタイプ

アイデア受付 → 軽量grilling → プロトタイプ作成 → 評価 → 本番移行候補作成 → ユーザー承認 → 本番仕様grilling

検証結果、利用シナリオ、採用・却下した案、再利用可能な素材、残課題を本番用Issueへ引き継ぐ。プロトタイプコードの本番昇格は例外扱いとし、ユーザー承認を必須にする。

### 本番開発

要件grilling → `CONTEXT.md`/ADR更新 → 実装計画 → 計画レビュー → ユーザー承認 → 実装 → テスト → PRレビュー → ユーザー承認 → マージ → 知識・残課題更新

## アーキテクチャ

共通マスターには、フロー定義、Skills、プロンプト、テンプレート、状態遷移、検証スクリプト、Codexアダプター、Copilotアダプター、fixtureを含める。

各プロダクトには`.ai-workflow/`を配置し、設定、状態、成果物、実行記録、残課題を管理する。状態ファイルはMarkdown本文とYAML front matterを組み合わせる。

### モード

- 自動モード：現在工程を判定し、次の承認ポイントまたはブロッカーまで進める
- 手動アシストモード：ユーザーが個別Skillを呼び出す。成果物・状態・承認条件は自動モードと共通にする

### 基本操作

- `setup`：プロジェクトを調査して導入・初期設定する
- `status`：工程、承認状態、ブロッカー、残課題を表示する
- `next`：次工程を判定し、承認ポイントまで進める
- `validate`：状態、成果物、リンク、互換性、工程遷移を検証する
- `update`：共通マスター更新候補を確認し、承認後に適用する

## 機密境界

会社環境でのテスト詳細、ログ、実行履歴、会社固有ポリシーは会社環境内に保存する。個人環境との自動連携は行わない。必要な場合は、ユーザーが機密性を確認して抽象化した情報だけをワークフロー改善用に手入力する。

## 初期版の完了条件

CodexとCopilotの双方で、fixtureプロジェクト上でsetupからprototype、production、PR、validate、セッションを跨いだ再開までの一連のフローを実行できること。導入・更新・検証・状態遷移の自動テストが通ること。
