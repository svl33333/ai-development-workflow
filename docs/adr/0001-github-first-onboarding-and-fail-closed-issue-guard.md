# GitHub起点の導入と正式Issue作成ガード

共通マスターはPC固有のローカルパスではなく、GitHub URLと固定したコミットを正式な取得元とする。正式Issueの作成・更新は、テーマ別のGrillingまたは明示的スキップ、仕様記録、人間の仕様承認、公開直前の最終承認が揃った場合だけCodexのCLIから許可し、条件不足・証跡不一致・外部差分があればGitHub APIを呼ばずに停止する。導入SkillとIssue作成ガードは別責務として扱う。

## Considered Options

- 共通マスターのローカルパスを継続する: 別PCで再現できず、導入元の所在が環境依存になるため不採用。
- 導入SkillだけでIssue作成を制御する: CLIや別経路からの外部操作を防げないため不採用。
- 状態ファイルの単一承認フラグだけで公開する: 承認対象との不一致や改ざんを検出できないため不採用。

## Consequences

導入結果は別PCで再現しやすくなる一方、GitHub取得・認証・状態証跡・最終承認の実装が必要になる。Issue本文は正式仕様だけに保ち、Grillingや暫定メモの履歴はリポジトリの文書とGit履歴で保持する。開発中の仕様変更は分類し、外部契約やスコープに影響する変更では実装を停止して再承認する。
