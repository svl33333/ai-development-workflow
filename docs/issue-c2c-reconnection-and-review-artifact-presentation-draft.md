# Issue draft: C2C再接続性とレビュー成果物提示の改善

## 背景

ワークフロー導入後、ファイル導入自体は成功していても、C2C接続確認時に導入元・別プロジェクトのWorkspaceやRepository情報が期待値として残り、導入先との照合に失敗することがある。

また、ユーザーへ仕様・Issue・実装計画・PRなどのレビューを依頼する際、レビュー対象の成果物がチャットやファイル表示で閲覧可能になっていることを必須条件として明文化・機械化できていない。

## 目的

1. Codex再起動後も、既存のC2C接続・ChatGPT Project・工程会話を安全に再利用できるようにする。
2. ユーザー向けレビュー依頼では、対象成果物を必ず閲覧可能な状態にしてからレビューを依頼する。

## 対応範囲

### C2C再接続・会話バインディング

- 導入先プロジェクトのWorkspace、Git remote、Branch、Project IDを正しい接続情報として扱う。
- 共通マスター側や別プロジェクトの接続情報を導入先へ引き継がない。
- ファイル導入済み、Project作成済み、C2C接続確認済み、会話再開可能を別状態として管理する。
- ワークスペースごとにC2C接続を1つだけ保持する。
- 既存接続の修復・再認証を優先し、新規接続や別Projectを推測して作成しない。
- ProjectはWorkspace、Repository、固有IDが一致する場合だけ採用する。
- 同じProject内でもIssue、工程、役割ごとに会話を分離する。
- 同一Issue・同一工程の再開時だけ既存会話を再利用する。
- 接続先不一致時は自動接続せず、期待値・実際の値・必要な操作を表示して停止する。
- 復旧不能時は`HUMAN_WAITING`または`BLOCKED`として状態を保存する。
- タスクID、Issue、工程、反復回数、メッセージIDで二重送信を防止する。
- 通信障害は有限回数のバックオフ再試行と状態再取得で扱う。
- 代替会話への切り替えは人間承認後に行い、新旧会話IDと交代理由を記録する。

### ユーザー向けレビュー成果物提示

- 仕様、Issue、実装計画、PR、マージ承認の各工程でレビュー対象を定義する。
- レビュー依頼前に、Codexのファイル表示機能などで対象成果物を開く。
- チャットには概要、確認ポイント、レビュー観点、絶対パスを提示する。
- 長大な成果物はチャットに要約を示し、全文を閲覧可能なファイルとして提示する。
- 成果物を閲覧可能にできない場合は、レビュー依頼・承認依頼を出さず停止する。
- 提示したファイル、コミットまたはハッシュ、時刻、提示方法、承認状態を記録する。
- 承認前に成果物が変更された場合、以前の提示・承認を無効化して再提示する。
- ChatGPT内部レビューではユーザー向け提示を必須にしないが、ユーザー承認が必要な工程では必ず提示する。

## 復旧順序

1. 保存状態を読み込む。
2. 導入先WorkspaceとGit remoteを確認する。
3. 同じC2C接続を診断・修復する。
4. ChatGPT Projectを識別・照合する。
5. Issue・工程・役割に対応する会話を照合する。
6. 同じ会話を再開する。
7. 状態と復旧結果を保存する。

Project一覧やメタデータを取得できない場合は、ユーザーにProject URLの入力を求め、名前・Workspace・Repositoryを照合する。
