# Codex向け実装計画作成依頼

あなたはCodexです。以下のGitHub Issueに対する実装計画を作成してください。

- 対象Issue: https://github.com/svl33333/ai-development-workflow/issues/1
- 仕様書: `docs/ai-development-workflow-package-spec.md`
- 今回のスコープ: Phase 1「共通フローの最小縦切り」

Issue本文、仕様書、リポジトリの現行ファイルをすべて確認してください。現行コードが少ないこと自体を前提にせず、実装に必要な構成・技術選択・環境制約を調査してください。

## 成果物

- 配置先: `design-docs-for-ai/`
- ファイル名: `issue1-phase1-shared-ai-development-workflow-implementation-plan.md`
- 本セッションの文脈を持たない別のAIエージェントが、その計画単体で実装に着手できる粒度にする

## 必ず含めるもの

- 変更・追加対象ファイルの一覧と内容
- 共通マスター、プロダクト側`.ai-workflow/`、Codexアダプター、Copilotアダプターの責務
- 状態ファイルと成果物の具体的なスキーマまたは例
- `setup` / `status` / `validate`の入力、出力、エラー、冪等性
- プロトタイプから本番用Issue草案への引き継ぎ形式
- Codex/Copilot双方のfixture構成とテスト方針
- GitHub CLI/API、利用ランタイム、外部依存の一次情報URL
- 会社環境の機密境界と、会社環境から共通マスターを読み取れない場合の扱い
- 品質管理、検証、互換性、更新方針
- 受け入れ条件との対応表

## Skills

必要に応じて、以下のCodex Skillsを明示的に読み込んで使用してください。

- `$code-naming`：計画内のサンプルコードや新規識別子の命名
- `$code-comments`：コード・テスト・コミットメッセージのコメント方針
- `$explain-visually`：計画作成後の構造確認と、人間向けの理解補助
- `$github-pr-review-draft`：PRレビュー案の構造と承認境界の確認

## 制約

- 外部サーバーや専用データベースをPhase 1では作らない
- 共通マスターから各環境への配布・更新は一方向
- 会社固有ポリシー、会社環境の詳細テストログ、実行履歴を共通マスターへ書き戻さない
- 既存ファイルは無断で上書きしない
- 仕様確定、本番移行、マージ、破壊的操作は人間の承認を必須にする
- 不明点や実環境でしか検証できない点は推測で確定せず、計画内に検証タスクとして残す
- トークン制限を前提に、工程ごとのコンテキスト選択とハンドオフサマリーを設計する

## 進め方

1. Issue、仕様書、現行コード、設定を調査する
2. 必要な一次情報を確認する
3. 実装計画を作成する
4. 計画を自分でレビューし、改善を3回繰り返す
5. 必須成果物、状態遷移、権限境界、テスト不足、Codex/Copilot間の差異、トークン制限への対応を再確認する
6. 最後に、残る未解決事項とPhase 1実装を開始できるかどうかを明記する

実装そのものは開始せず、実装計画の作成に限定してください。
